# 决策汇报结构模板与汇报战术

## 决策汇报 13 页骨架（实测验证版）

适用于立项汇报、资源申请、方案评审。每页一个 action title，页脚标数据口径与页码。

| # | 页面 | 要点 |
|---|---|---|
| 0 | 封面 | 项目命名即立场（"统一底座"而非"内存优化"）；汇报人/日期/口径声明 |
| 1 | 执行摘要 | 核心主张 + 三发现（数字）+ 一请求 |
| 2 | 问题界定 | 现状可视化（矩阵/热力图），只呈现"多与散" |
| 3 | 影响量化 | 3-4 个大数字账本 + 测算口径，全部可复算 |
| 4 | 业界对标 | 三条既有路线对比表 + 一句对标结论，堵"自嗨"质疑 |
| 5 | 方案总览 | 一张架构图：左"乱"右"整"，一页看懂 |
| 6 | 收益机制 | 分模式拆解收益来源，每个配可视化 |
| 7 | 风险与对策 | 主动亮风险 + 对策 + 验证时点（深度分全在这页） |
| 8 | 测算模型 | 公式摊开 + 敏感性说明，邀请复算 |
| 9 | 路线图 | 分阶段 + **量化退出条件**（敢设止损线 = 工程素养信号） |
| 10 | 组织与治理 | 机制设计：接入激励、责任归属、牵头方建议 |
| 11 | 愿景 | 本项目在更大蓝图中的位置（一步即可，勿过度展开） |
| 12 | 决策请求 | 只请一件事，明确到"2 人 × 6 周"粒度；风险边界与交付物并列 |
| 13 | 附录 | 口径说明、待实测清单、结构速览 |

节奏参考（15 分钟版）：问题 3 分钟 → 方案 4 分钟 → 风险 3 分钟 → 路线与请求 3 分钟，留提问时间。

## Q&A 预案设计法

会前准备 8-10 个尖锐问题，每题答案控制在 30 秒内。高频问题清单：

1. 为什么不用 X 方案（一定存在一个现成替代方案）？
2. 核心组件挂了会怎样（失败模式）？
3. 有没有隐性成本（常驻/维护/迁移）？
4. 合规/审核风险？
5. 相关团队凭什么配合（激励设计）？
6. 版本/规模冲突怎么治理？
7. 收益什么时候可见（时间线）？
8. 与现有系统/上游路线冲突吗？
9. 投入产出比怎么算？
10. 你要多少资源、多久（决策粒度）？

**心法**：答得越坦然，说明考虑得越深；当场答不出的，记为"验证项"写进 POC 清单——这同样是专业表现。

## 会前会后动作（明线之外的胜负手）

| 时间 | 动作 | 目的 |
|---|---|---|
| T-7 天 | 向直属领导预沟通全貌 | 让他成为背书人而非被惊吓者 |
| T-5 天 | 拉 1-2 个数据最大/关系最好的相关方过数据 | 变"单方提案"为"联合贡献" |
| T-3 天 | 预演反对者视角（替代方案派/资源派） | Q&A 预案实战化 |
| T-1 天 | 全部数字实测校准 + 请一位同事复核 | 数字出错 = 汇报死亡 |
| T+1 天 | 24 小时内发出纪要 + 行动项（谁/何时/交付什么） | 纪要撰写权 = 叙事定义权 |
| T+7 天 | 跟进决策进展，主动补材料 | 保持"推进者"形象 |

## 数据与版式纪律

- 每个关键数字标注来源与口径；估算值明确标注"示意，POC/实测后替换"。
- 页脚统一放口径声明与页码，正文脚注放单条数据来源。
- 可视化只服务论证（矩阵表冲击、架构图理解、时间轴推进），不加装饰性图表。
- 敏感数据匿名化（团队/产品用代称），动机表述去政治化（只讲降本增效，不点评任何团队）。

## 红线清单

- ❌ 不点名任何团队的浪费——数据用代称，问题讲"结构性"不讲"某人造成的"。
- ❌ 不贬低替代方案——讲互补与覆盖差异，替代方案的拥趸可能是你的反对票。
- ❌ 决策请求不超过一个——多个请求等于把选择成本丢回给领导。
- ❌ 愿景不承诺正文未铺垫的收益——收尾抬格局可以，画饼不行。
