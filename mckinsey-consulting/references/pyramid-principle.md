# 金字塔原理：结构与标题写法

## 纵向结构：结论先行 + 疑问回答式对话

每个层级只做两件事：

1. **给出该层结论**（读者最先看到的一句话）；
2. **引发读者唯一的疑问**，下一层全部内容都在回答这个疑问。

推演示例：

```
L1 结论：共享库一期可释放约 72% 的重复 ROM 占用
  └─ 读者疑问：72% 怎么来的？可信吗？
L2 结论：测算模型透明、可复算（重复打包 716MB − 宿主化 200MB）
  └─ 读者疑问：重复 716MB 的依据？
L3 证据：8 类公共库 × 10 个 APP 的拆解矩阵（示意口径已标注）
```

检验法：从任意一层遮住下层，只看结论能否自然引出"凭什么？"——能，则纵向成立；不能，说明该层不是结论而是事实罗列。

## 横向结构：演绎与归纳的选择

| 方式 | 结构 | 适用场景 | 风险 |
|---|---|---|---|
| 演绎 | 大前提 → 小前提 → 结论 | 读者认同前提、需要严密推导 | 链条长时读者掉队 |
| 归纳 | 同类事实 → 共性结论 | 证据多、读者要快速抓重点 | 被质疑"样本够吗" |

汇报场景优先归纳（读者时间少），论证场景用演绎（读者要逻辑严密）。同一层内**只用一种**，混用会让读者抓不到顺序逻辑。

## MECE 检验清单

拆解完任何议题树，逐条过：

- [ ] 把任意两个分论点放在一起，能否合并成一件事？（ME 检验）
- [ ] 有没有一个明显角度没被任何分论点覆盖？（CE 检验）
- [ ] 每个分论点是否在同一拆解轴上？（按维度拆就不要混入按流程拆的项）
- [ ] 分论点数量 3-5 个——超过 5 个说明拆得太细，先合并再深挖。

## Action Title 写法

**公式：判断句 = 主体 + 观点/量化结论。** 标题本身就要传递信息，读者只读标题也能走完整篇逻辑。

| ❌ 话题式（无信息量） | ✅ 判断式（action title） |
|---|---|
| 网络库与图片库对比 | 网络库重复打包 81MB，是图片加载库的 0.66 倍 |
| 方案介绍 | 方案：一个共享宿主、一个轻量桩、三种收益模式 |
| 风险分析 | 六大风险均有对策，POC 第一周验证最关键可行性 |
| 收益情况 | ROM 释放约 72%，TOP3 库常驻内存下降约 70% |
| 实施计划 | 三阶段推进，每阶段设量化退出条件 |

常见错误：
- 标题带"分析""介绍""情况"等无立场词——删掉重写；
- 一句话里塞两个论点——拆成两页；
- 标题正确但平淡（"成本可以降低"）——把最有说服力的数字或判断放进去（"成本降低约 72%"）。
