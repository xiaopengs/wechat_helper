反观点 · 开发者生态

开发者大会已死，
这场演讲就是证据

听完 Google 开发者大会上一场 Agent 架构演讲，我发现台上讲的每一个字，都不是说给人听的

这届 Google 开发者大会，我印象最深的是一场关于 Medo 的技术演讲——一个跑在 Google Cloud 上的 Agent 应用构建产品。演讲者用了九个章节，把他们的四层自研架构从头到尾拆了一遍：Agentway 托管会话、Sandbox 控制面、弹性底座、AgentDebug 平台、数据飞轮与 AgentLake。

内容本身非常扎实。但听着听着，一个越来越强烈的违和感击中了我：这场演讲里几乎没有一个环节，是围绕"人写代码"设计的。

Sandbox 是给 Agent 跑的，会话是给 Agent 托管的，数据湖是给算法迭代喂的。人在哪里？人在最上面那一层——"UX 体验"，负责说一句话，起一个任务。然后就没有然后了。

过去的开发者大会，台上讲"这个 API 怎么调用"，台下记笔记回去写代码。这一场，台上讲的是"Agent 生成的代码怎么跑、跑出来的数据怎么回流训练 Agent"。听众还在记笔记——但记的东西，他们这辈子可能都不会亲手用到。

这篇文章不是演讲纪要。我想说的是一个更残酷的判断：这场演讲本身就是开发者大会消亡的证据——连舞台中央的技术内容，都已经默认代码不是人写的了。

01

四层架构里，人的位置只剩一句话

先看这场演讲的骨架。Medo 的四层自研架构，全部建在 Google Cloud 边界内：

层 干什么 给谁服务
L1 产品 Medo 产品界面：对话、应用画布、实时预览 人 · 说一句话，起一个任务
L2 编排 Agentway 托管会话，三种 Agent↔Sandbox 拓扑 Agent · 跑在 GKE，调 Gemini
L3 执行 Sandbox 统一底座：gVisor · 池化 · COW Agent 生成的代码
L4 数据 AgentDebug 回放评测 + AgentLake 数据湖 算法 · 每次执行全量埋点回流

看清楚这张表的逻辑：四层里三层半在服务 Agent，人只占有 L1 的一个对话框。用户请求从上往下穿，运行数据从下往上回流——整个闭环转起来之后，中间不需要任何一个"开发者"角色。

这就是我在大会现场感到荒诞的原因：一场"开发者大会"上的核心技术演讲，讲的却是一个把开发者从链路里抽掉的架构。而且讲得非常自然，非常理所当然——仿佛这已经是所有人的共识。

02

新发布的接口，已经不是给人设计的了

以往开发者大会的主角是新 API、新 SDK——教人怎么接。这场演讲里出现的"接口"，画风完全不同。看 Agentway 托管会话的设计：三种运行入口（Managed Session 有状态会话、Serverless Fn 无状态函数、Stateful Object 长驻单实例）统一成一套会话抽象；每个会话再拆成逻辑层和物理层——逻辑层装会话内容、代码、Agent 配置，物理层装计算、文件系统、网络，两层解耦。

这套设计图什么？图的是逻辑状态可以在物理实例间自由迁移：断线续接、fork rollout、60 秒内故障接管。再看 Sandbox 内部：sandboxfs 用 reflink 秒建 COW 工作区、Landlock 内核级只准写自己目录；sandboxsh 走 WebSocket 转发、全量留痕审计；sandboxnet 出站全过代理、密钥永不进沙箱。

请注意这些设计的"用户画像"：需要 fork、需要审计、需要隔离、密钥不能进环境——这不是给人准备的开发环境，这是给一个不可信、会犯错、需要被全程监控的执行体准备的笼子。这个执行体，就是 AI。

过去平台设计接口，一切巧思——命名直觉、参数好记、文档友好——都是为讨好人类认知。而这场演讲展示的接口设计哲学，全部是围绕 Agent 的执行特性 展开的：Runtime 可插拔，"加一种后端 = 实现一个 Runtime 接口"。接口的消费者变了，接口的设计语言就整个变了。

这才是大会真正的信号：能力模块设计没有消失，但它的服务对象从人换成了 Agent。那些精心设计给人用的封装，正在被一层层绕过；而新设计的模块，从第一天起就没打算让人亲手碰。

03

最扎心的一页 PPT：数据飞轮

整场演讲最震撼我的，是最后一章"数据飞轮 & AgentLake"。

机制是这样的：每次使用沉淀数据，全量落进 AgentLake——L0 用户交互行为（click / input / accept / abandon），L1 应用数据与源码（PRD → repo → build → artifact），L2 Agent 轨迹（state → action → observation），L3 Benchmark 开发数据。底下是 BigQuery Iceberg 列存、向量召回、DuckDB 分析、Ray 并行加工，上面接 Dashboard、AgentDebug、Benchmark 三个出口。一条轨迹能在线对比、能提取重放、能 fork 出来改工具改指令再评估——评估通过就上线，上线的新运行又落回轨迹库，闭环自己转起来。

然后演讲者放出了一个数字：

超长轮次样本里约 30% 在反复改同一个 bug、甚至死循环，同一问题修 3–50 次——这些恰恰是驱动算法迭代的金矿。

细品这个逻辑：Agent 犯的每一次错、打转的每一个死循环，都被全量记录、采样、标注，变成下一轮算法迭代的训练燃料。系统的每一次失败，都在让系统变强。每日轨迹回流，周更算法上下线——这个迭代节奏，不是"学手艺"的节奏，是"养模型"的节奏。

再对比一下：一个开发者踩了坑，教训存在他的脑子里，跳槽就带走；一个 Agent 踩了坑，教训存在 AgentLake 里，全平台永久复用。个人的经验在贬值，系统的数据在复利——这就是飞轮和人脑的区别。

04

那开发者大会还剩下什么？

值得停下来想一想：既然内容已经变成"给 Agent 搭底座"，为什么大会还一届比一届盛大？

一是大会早已不是技术事件，是营销事件。它的真实观众不是台下的开发者，是直播镜头外的生态、客户和资本市场。演讲里每一个名词——GKE、Gemini Enterprise Agent Platform、BigQuery、Filestore、Cloud Storage——都是生态绑定的广告位。开发者是布景板。

二是生态信仰需要定期充值。把多种云服务重新组合、补齐单个服务的短板——演讲者自己说这是"搭 infra 的核心工作"。翻译成大白话：深度绑定一朵云的每一块积木。仪式感本身就是一种生态税，你交的不是钱，是两天时间和一份忠诚。

三是惯性。信息分发的功能已经被架空——演讲 PPT 挂出来当天，AI 比你消化得更快、更全、更准。但一台运转了十几年的巨型机器，不会因为底层逻辑消失就立刻停下。

所以我的判断：开发者大会不会被取消，只会被稀释——教人写代码的内容逐年消失，给 Agent 搭基建、给生态讲信仰的内容逐年膨胀，直到它和一场产品发布会再无任何区别。

05

给开发者的三条建议

1. 把大会当情报站，别当课堂。这场演讲真正值钱的信息不是技术细节，而是方向判断：头部团队已经在"四层架构 + 数据飞轮"上卷 infra 了。至于 gVisor 怎么配、Runtime 接口怎么实现——让 AI 课后去补，它比你学得快。

2. 从"会写代码"升级到"会设计闭环"。Medo 架构里最难替代的不是代码，是那些设计决策：逻辑/物理为什么解耦、轨迹为什么要做成可重放可 fork 的一等资产、30% 的死循环数据为什么是金矿。判断力是仅剩的护城河。

3. 警惕"生态忠诚"的隐性成本。整套架构建在一个 Google Cloud 边界内，跑得越顺，迁出来越难。平台设计模块是为了它的生态战略，不是为了你的架构自由。AI 时代切换成本在崩塌——忠诚度应该在崩塌之前先被你主动清算一遍。

演讲结束，台上放完最后一页"越用越准"的飞轮图，台下鼓掌。

我环顾四周突然意识到：这场演讲的每个章节——托管会话、沙箱、弹性底座、轨迹回放、数据飞轮——合起来其实只讲了一件事：一个不再需要开发者的开发系统，应该长什么样。而它出现在开发者大会的舞台上，这本身就是这个时代最诚实的注脚。

大会还会一年年办下去，
但台上讲的东西，已经越来越不是说给人听的了。

注：本文基于 Google 开发者大会现场一场 Medo 架构演讲（四层自研架构 / Agentway / Sandbox / 弹性底座 / AgentDebug / 数据飞轮与 AgentLake）的真实内容写成，技术细节以演讲 PPT 为准；观点评论仅代表作者本人。
